# Котлетик-добросусід 🏠

Telegram-бот для чату сусідів, який допомагає зберігати людяний тон.
Авторський проєкт Владислава «Котлети» ([@KotletaVlados](https://github.com/KotletaVlados)).

Час зараз важкий: тривоги, прильоти, відключення світла, і нерви в усіх на межі. У будинкових
чатах через це часто спалахують сварки. Котлетик-добросусід нікого не банить і не повчає. Здебільшого
він мовчить і подає голос лише тоді, коли розмова переходить на особистості. Тоді він м'яко
нагадує, що по той бік екрана такі самі сусіди, і повертає розмову до суті.

## Що вміє

- **Гасить сварки.** Помічає образи, погрози й цькування та відповідає коротко й тепло, ні на
  чий бік не стає. На звичайні скарги, жарти чи лайку на ситуацію (а не на людей) не реагує.
- **Знайомить сусідів.** Новачок пише в чат лише після знайомства: бот вітає його кнопкою
  «👋 Представитися», в особистих питає ім'я та квартиру, відкриває чат і замінює привітання на
  «Знайомтеся: Олена, кв. 45». Тим, хто був у чаті раніше, бот до трьох разів (раз на 3 дні)
  нагадує представитися. Представлення розпізнає у звичайному повідомленні («Я Олена, кв. 45»),
  у вільній відповіді в особистих або через `/iam Олена, 45`.
- **Відповідає на звернення, але лише знайомим.** Якщо згадати бота або відповісти на його
  повідомлення, він відповість. Тому, хто ще не представився, по суті не відповідає: спершу
  ім'я та квартира. Коли чогось не знає, так і каже, а не вигадує.
- **Має характер.** На «ти хто такий?» відповідає дотепно, на наїзди — впевнено й з іронією,
  але без образ і не втягується в перепалку.
- **Пам'ятає про безпеку.** Якщо хтось пише про пожежу, газ чи загрозу, нагадає номери 101–104.

Команди: `/rules`, `/iam`, `/who`, `/forgetme`, `/help`. Для адміністраторів: `/status`,
`/letin` (відповіддю на привітання новачка — пустити без знайомства), `/intro`
(оголошення-знайомство), `/pause`, `/resume`.

## Захист

Системний промпт рано чи пізно витягнуть, тому захист тримає код, а модель лише пропонує рішення
за схемою.

- Переписка йде в модель JSON-рядками: перенос рядка, нік у профілі чи `</chat>` не підроблять
  чужу репліку.
- Представлення прив'язується до автора повідомлення, а ім'я та квартиру перевіряє код
  (лише літери; без посилань, `@`, «адмін», «ОСББ»).
- Бот ніколи не публікує посилань, `@ніків`, номерів карток, IBAN і телефонів (крім 101–104):
  таку відповідь він просто не надсилає. Дозволені домени можна задати в `ALLOWED_LINK_DOMAINS`.
- Ліміти на людину: 3 звернення за 10 хвилин і 20 на добу, 10 спроб знайомства в особистих.
  Тролль не змусить бота відповідати щохвилини і не спалить бюджет за всіх.
- Екстрена пам'ятка повторюється не частіше ніж раз на 10 хвилин.
- Новачок не сидить без права писати вічно: через 24 години (`GATE_TIMEOUT_HOURS`) чат
  відкривається сам, а адмін може пустити раніше через `/letin`. Мут, поставлений живим
  адміністратором, бот не знімає.

## Як працює

1. Бот читає повідомлення групи (для цього він має бути адміністратором, див. нижче).
2. Коли в чаті затихає на 20 секунд (але не пізніше ніж за хвилину), нова пачка повідомлень
   разом із контекстом іде в [Claude Haiku 5.5](https://www.anthropic.com/claude). Модель
   повертає структуровану відповідь: рівень напруги, чи варто втрутитися, текст і знайдені
   представлення.
3. Остаточне рішення ухвалює код. Сам бот говорить лише при `conflict`/`hostile`, не частіше
   ніж раз на 10 хвилин і не більше 15 разів на добу. Це все налаштовується.

Бот працює лише в групах, куди його додав власник (`OWNER_IDS`), а з чужих груп одразу виходить.
Тож ніхто не зможе витрачати ваш API-ключ у своєму чаті.

## Вартість

Haiku 5.5 коштує $0.10 за мільйон вхідних токенів і $0.50 за мільйон вихідних. Один аналіз
займає ~3–4 тис. токенів, тож чат на 150–200 людей обходиться в центи на добу. Є запобіжник
`MAX_LLM_CALLS_PER_DAY`.

## Приватність

- Повідомлення зберігаються в локальній SQLite лише як контекст і видаляються через 3 дні.
- Текст повідомлень надсилається в Claude API для аналізу. Варто чесно сказати про це в чаті:
  оголошення `/intro` про це згадує.
- Представлення (ім'я та квартира) видно через `/who`; `/forgetme` видаляє своє.

## Запуск

### 1. Бот у Telegram

1. Створіть бота в [@BotFather](https://t.me/BotFather) і візьміть токен.
2. За бажанням змініть ім'я (`/setname` → «Добросусід») і опис. Аватарка Котлетика лежить у `assets/avatar-640.png`, її ставлять через `/setuserpic` у BotFather.
3. Напишіть боту `/start` в особисті: він покаже ваш Telegram ID для `OWNER_IDS`.

### 2. Сервер

```bash
sudo useradd --system --home /opt/dobrosusid-bot --shell /usr/sbin/nologin dobrosusid
sudo git clone https://github.com/KotletaVlados/dobrosusid-bot /opt/dobrosusid-bot
cd /opt/dobrosusid-bot
sudo python3 -m venv .venv && sudo .venv/bin/pip install -r requirements.txt

sudo cp .env.example /etc/dobrosusid-bot.env      # заповніть токен, ключ, OWNER_IDS
sudo chown root:dobrosusid /etc/dobrosusid-bot.env && sudo chmod 640 /etc/dobrosusid-bot.env

sudo cp deploy/dobrosusid-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now dobrosusid-bot
journalctl -u dobrosusid-bot -f
```

### 3. У групі

1. Додайте бота в групу (саме з акаунта власника). Він привітається й попросить усіх представитися.
2. **Зробіть бота адміністратором** з одним правом — «Блокувати користувачів»
   (`can_restrict_members`), воно потрібне, щоб новачок писав лише після знайомства. Решту прав
   вимкніть, «Анонімність» теж. Без адмінки Telegram показує ботам лише команди та відповіді на
   їхні повідомлення (privacy mode).
3. `/status` у групі покаже, чи бачить бот усі повідомлення і чи може обмежувати новачків.

У BotFather бот не потребує Inline, Guest Mode, Business, тем в особистих і перевірки заявок на
вступ — кожна з цих функцій лише зайвий вхід для чужих повідомлень. Коли бот уже в чаті,
`/setjoingroups` → Disable.

## Розробка

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest
```

Локальний прогін модератора по HTML-експорту Telegram Desktop (`messages.html`,
`messages2.html`, …):

```bash
.venv/bin/python -m tools.replay --export "$EXPORT_DIR" --out "$REPLAY_OUT" --stub
.venv/bin/python -m tools.replay --export "$EXPORT_DIR" --out "$REPLAY_OUT_REAL" \
  --env-file "$ENV_FILE" --from 2026-11-01 --to 2026-11-03 --max-calls 50
```

Експорт і результати приватні: тримайте їх **поза репозиторієм**, не додавайте до
комітів чи PR. `--out` має бути новим каталогом поза всіма git worktree; інструмент
створить його з правами `700` і запише `batches.jsonl` та `summary.json`.
`--stub` працює без мережі й ключа, лише перевіряє механіку. Реальний режим надсилає
контекст у Claude API та читає `ANTHROPIC_API_KEY` з оточення або `--env-file`
(оточення має пріоритет); Telegram-токен не потрібний. Типовий ліміт — 50 викликів,
автоматичні повтори API вимкнені; повторний запуск потребує нового каталогу.

Використовуються продакшн-аналіз, промпт, контекст на 40 повідомлень, debounce
20/60 секунд і ліміти втручань у часі історії; налаштування можна взяти з env-файлу.
Дати включні, у `TIMEZONE` бота (типово `Europe/Kyiv`). Службові записи й повідомлення
без тексту пропускаються. Автори з однаковим відображуваним ім'ям мають спільний
синтетичний id; HTML не дає надійно відновити ботів і звернення через їхні Telegram
імена, але звернення за ім'ям персони розпізнаються звичайним кодом бота.
Гіпотетичні відповіді не додаються до історичного контексту. Вартість — оцінка за
ставками з цього README, які можна змінити через `--input-usd-per-million` і
`--output-usd-per-million`; у stub токени та вартість нульові. Реальні дані й
підкручування промпту — окремий наступний крок після появи локального API-ключа.
